📝 总体评估

📋 总体评估

项目概况：NodeLite 是 Rust Server–Agent 监控系统，使用 Tokio/Axum、SQLite 和 Vue/Pinia 前端。仓库已经具备较完整的认证、数据清洗、测试、运维文档及发布基础设施，适合继续沿现有架构迭代。

主要风险：19 项独立发现：4 High、14 Medium、1 Low；没有确认 Critical。最高风险集中在 Linux Agent 续期凭证无法落盘、非事务历史迁移、并发设置覆盖，以及密码撤销不能关闭既有浏览器 WebSocket。

亮点：完整 Rust 和前端单元测试通过，安全/依赖/静态检查通过；注册表持久化、输入限额、查询缓存和认证限流有明确实现。检测结果不应被解释为所有异常路径已覆盖。

优先修复：先处理 F01–F04，再处理跨 writer 快照、限速应用收敛、历史失败诊断及前端持续同步；同时将真实浏览器联调加入 CI。建议把四项 High 作为下一次稳定发布的阻断项。

总评：6.5/10，等级 B：工程基础可用，可靠性与发布边界需要有计划修整。局部修复足够，没有证据支持整体重写。所有“Confirmed”表示代码路径已确认；仅 F04 做了真实服务复现，F02 做了 SQL 级中断复现，不代表其他风险均已在生产触发。

F01. 官方 Linux 安装权限阻止 Agent 持久化续期 Token

HighConfirmed
Category: StabilityConfidence: HighAffected area: Agent 安装与凭证续期

问题 / Problem：配置目录和状态目录为 root:服务组、0750；配置为 root:服务组、0640；进程使用 nodelite-agent 用户。续期需在配置目录创建临时文件并 rename，而默认 /etc 还受 ProtectSystem=full 只读限制。失败只记日志，内存 Token 仍更新。

影响与真实失败场景 / Why it matters · Realistic failure scenario：官方 Linux 安装后发生自动或手动续期，新凭证只存在内存；旧 Token 的 10 分钟宽限期过去后重启 Agent，将以磁盘旧凭证连接失败。影响持续监控及无人值守恢复。
