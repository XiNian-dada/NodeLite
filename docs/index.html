NodeLite 部署指南

基于 Rust 构建的轻量级高性能监控面板。几分钟完成安装，支持单文件交付、无锁广播、Linux 套餐限速与多通道告警。

推荐上线流程

先让服务端和第一台 Agent 连通并验证面板显示，再配置域名 TLS 反向代理、告警通道与安全加固。

第 1 步 一键安装服务端 (nodelite-server)
第 2 步 配置反向代理 (Nginx / Caddy)
第 3 步 签发并执行 Agent 安装命令

快速部署

根据你的实际环境，选择最适合的部署路径：

第一步：一键安装服务端

在主控机（Linux + systemd）上执行，自动识别架构并配置服务

服务端一键安装命令 
curl -fsSL https://github.com/XiNian-dada/NodeLite/releases/latest/download/install-server.sh | sudo sh

安装器会自动引导你配置安装目录（默认 /opt/nodelite）、监听端口、对外访问域名以及管理员强密码，随后自动生成 systemd 服务并启动。

第二步：签发并安装被控端 (Agent)

在服务端签发含 15 分钟有效期的临时 Token 命令，粘贴到被控子机执行

在服务端签发节点安装命令 
/usr/local/bin/nodelite-server \
  --config /opt/nodelite/config/server.toml \
  install-agent \
  --node-id hk-01 \
  --node-label "Hong Kong 01"
在目标子机（Linux / macOS）上粘贴执行服务端输出的命令 
curl -fsSL https://monitor.example.com/install/install-agent.sh | \
  NODELITE_AGENT_INSTALL_TOKEN='one-time-token' sh -s -- \
  --bootstrap-url https://monitor.example.com/install/bootstrap \
  --base-url https://github.com/XiNian-dada/NodeLite/releases/latest/download
安全说明

一次性 Token 仅用于首次握手获取长期节点凭据。长期 Token 会安全保存于 Agent 的 0600 权限配置文件中，绝不会在命令行或 URL 中泄露。

前置条件与端口规划

  • 一台 Linux 主机用于部署服务端，开放 80/443 供反代访问
  • 一个解析到服务端的域名（生产环境强推荐配合 HTTPS / WSS）
  • 服务端默认监听 127.0.0.1:8080，由前置 Nginx/Caddy 转发
  • 被控子机仅需出站访问服务端的 443 端口，无需在子机放行任何入站端口

部署就绪检查清单

  • 执行 systemctl status nodelite-server 确认服务端处于 running
  • 浏览器打开面板域名，输入安装时生成的账号密码成功登录
  • 子机执行完安装命令后，面板在 2 秒内刷新出该节点的 CPU、内存与流量卡片
  • 访问 /metrics 端点可获取 Prometheus 指标数据

进阶配置与反向代理

生产部署的标准配置指南，包含反代、手工安装与 Prometheus 接入。

Nginx 反向代理配置（强烈推荐） 终结 HTTPS / WSS，代理静态页面与长连接

将以下配置保存为 /etc/nginx/conf.d/nodelite.conf。请将域名与证书路径替换为你的实际信息：

完整的 Nginx 配置模板 
server {
    listen 443 ssl http2;
    server_name monitor.example.com;

    ssl_certificate     /etc/letsencrypt/live/monitor.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/monitor.example.com/privkey.pem;

    # 1. 静态面板与 API 路由
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 2. Agent 与浏览器 WebSocket 连接 (必须配置 Upgrade 与长超时)
    location /ws {
        proxy_pass http://127.0.0.1:8080/ws;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }

    # 3. Agent 安装脚本与 bootstrap 端点
    location /install/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
Caddy 用户提示

如果使用 Caddy，仅需简单的 reverse_proxy 127.0.0.1:8080 即可，Caddy 会全自动申请并续签 SSL 证书，并天然支持 WebSocket 代理。

手动解压与配置部署 适合 Docker、离线环境或需要深度定制目录结构的用户
  1. 从 GitHub Releases 下载对应的 nodelite-server-linux-musl.tar.gz 二进制包；
  2. 将可执行文件放置于 /usr/local/bin/nodelite-server 并赋予执行权限；
  3. 创建配置目录 /opt/nodelite/config，复制 config/server.example.toml 至 server.toml 并调整参数；
  4. 创建独立服务账号 nodelite-server，配置 systemd unit 启动；
  5. 执行 install-agent 签发子机安装命令。
Prometheus /metrics 接入与 Grafana 看板 内置标准 Prometheus exposition 格式抓取端点

/metrics 端点与前端控制台共享只读 Basic Auth 鉴权。可在 prometheus.yml 中添加如下配置：

prometheus.yml 抓取配置 
scrape_configs:
  - job_name: 'nodelite'
    scheme: https
    metrics_path: /metrics
    basic_auth:
      username: '<readonly-username>'
      password: '<generated-strong-password>'
    static_configs:
      - targets: ['monitor.example.com']

官方 Grafana 看板模板位于仓库的 ops/grafana/nodelite-dashboard.json，直接在 Grafana 中选择 Import JSON 即可一键导入。

告警通知与 Linux 限速

NodeLite v3.0 的杀手级特性：多通道即时告警、每日巡检摘要以及内核级 VPS 流量限速。

1. 配置告警通道与每日巡检报告

在 server.toml 中启用并配置 SMTP 邮件或 Webhook（Telegram/Discord）

server.toml 中的 [alerts] 配置片段 
[alerts]
enabled = true

# SMTP 邮件通知
[alerts.smtp]
enabled = true
host = "smtp.example.com"
port = 587
username = "alert@example.com"
password = "your-email-password"
sender = "alert@example.com"
recipients = ["admin@example.com"]
send_resolved = true

# Webhook 机器人通知 (Telegram / Discord / 钉钉 / 飞书)
[alerts.webhook]
enabled = true
url = "https://api.telegram.org/bot<TOKEN>/sendMessage?chat_id=<CHAT_ID>"
send_resolved = true

# 每日定时巡检报告 (每天 09:00 汇总 24 小时健康度)
[alerts.inspection]
enabled = true
local_time = "09:00"
delivery = ["smtp", "webhook"]

2. 启用 Linux Agent 流量套餐限速 (tc)

当 VPS 流量超出预设计费套餐时，由 Agent 端内核动态实施限速，杜绝高额超标账单

安装或升级 Agent 时，仅需传入 --enable-traffic-control 参数：

启用限速能力的 Agent 安装命令 
curl -fsSL https://monitor.example.com/install/install-agent.sh | \
  NODELITE_AGENT_INSTALL_TOKEN='one-time-token' sh -s -- \
  --enable-traffic-control
环境依赖要求

被控机需安装发行版自带的 iproute2（包含 tc 工具）。Agent 仍以非特权用户运行，仅按最小权限原则授予 CAP_NET_ADMIN，其余 systemd 安全沙箱依然完好保留。

排障与常见问题 (FAQ)

汇总部署与生产运行中最常见的问题诊断与应对措施。

首先在被控机上排查 Agent 日志：

sudo journalctl -u nodelite-agent.service -n 50 --no-pager

常见排查清单：

  • 反向代理是否漏掉了 WebSocket 转发头（检查 Nginx 的 proxy_set_header Upgrade $http_upgrade; 与 Connection "upgrade";）；
  • Agent 配置的服务器地址必须以 wss:// 开头（生产环境严格校验 TLS 证书）；
  • 子机是否无法解析服务端域名或被机房安全组拦截了出站 443 端口。

出于防暴力猜测的安全机制，服务端签发的一次性 install token 有效期为 15 分钟。若超时未执行，只需在服务端重新执行一次 install-agent 签发命令即可。

如果你的服务端前面使用了外部反代、CDN 或 Cloudflare WAF，所有 Agent 请求可能会以相同的代理 IP 到达服务端，从而触发防刷连接池阈值。

解决方案：在 server.toml 的 trusted_proxies 中添加前置反代的 CIDR 網段。如果反代与服务端在同一台机器上，则无需额外配置。

在 server.toml 的 [auth] 段配置 enable_2fa = true 与 totp_secret 即可开启二次动态验证。

若丢失 2FA 设备或遗忘密码，只要拥有服务端主机权限，直接编辑 server.toml：修改 password 并将 enable_2fa = false，执行 sudo systemctl restart nodelite-server 即可瞬间恢复访问。

在 Linux 下通过 systemctl status 查看到的 cgroup 内存（MemoryCurrent）包含 SQLite WAL 产生的可回收文件页缓存（Page Cache），不能等同于进程自身的堆内存占用或泄漏。

NodeLite 进程本身的纯私有驻留内存（RSS/PSS）服务端在常规负载下仅为 10~15MB，Agent 通常小于 2MB。详见仓库根目录的 docs/memory-measurement.md。
