# Agent 凭证续期与安全升级

## 升级顺序

先升级 Server，再升级所有 Agent。新协议通过 Hello 协商落盘确认能力，不提高常驻 Agent 的权限。
新 Server 允许旧 Agent 继续用有效 token 上报，但不会再无确认地轮换其凭证；旧 Agent 必须在现有 token 过期前升级。
新 Agent 与旧 Server 的监控协议仍兼容，不过只有双方都升级后才能获得两阶段续期保证。

升级器在停止旧 Agent、替换二进制或迁移配置之前，用下载并校验过的候选程序验证磁盘凭证：

```bash
sudo /path/to/candidate-nodelite-agent --config /path/to/agent.toml --check-credentials
```

它通过独立的 `/ws/preflight` WebSocket 端点检查身份，不注册节点、不轮换 token，也不会挤掉在线 Agent。
反向代理需要同时转发 `/ws` 与 `/ws/preflight`；README 的 `location /ws` 配置已经覆盖两者。
预检有独立的短连接配额（最多 16 个、每 IP 最多 2 个，且不超过已有 WS 配额），并沿用 Agent 认证封禁、帧大小和握手超时。
Server 未升级、网络不可达或磁盘凭证无效时，升级失败，旧程序和正在运行的服务保持不变。

## 两阶段续期

1. Server 原子保存候选凭证的 Argon2id 哈希并同步文件、目录，原凭证仍保留其原有有效期。
2. Agent 写入随机命名、0600 的独占临时文件，同步文件、原子替换配置并同步父目录；成功后才替换内存 token、发送事务确认。
3. Server 收到当前在线会话的确认后激活候选凭证。手动续期接口也等待确认，而不是只把“已发送”当作成功。

确认前断连或重启时，注册表中的候选哈希仍可认证；Agent 从磁盘重新读取并同步凭证后，通过正常 Hello 恢复激活。
Agent 的阻塞写任务即使被会话取消，仍持有配置锁，下一次重连读取会等待它结束。
目录同步错误不会被当作成功。配置解析错误不会把含 token 的原始 TOML 写入日志。
管理员重新签发或删除节点会撤销其所有候选凭证，旧事务确认不能复活已撤销的 token。

## 权限与失败恢复

Linux 的活跃配置位于 `/var/lib/nodelite-agent/agent.toml`，目录由专用服务用户拥有，权限 0700；文件为 0600。
systemd 仅允许该状态目录写入。常驻 Agent 不运行 sudo；安装或升级时，管理员一次性以 root 权限迁移配置和调整所有权。
macOS 仍沿用项目已有的实验性 launchd/root 安装方式，本次没有扩大其权限。

如果旧 Agent 曾经只在内存里更新 token、没有成功落盘，磁盘中的旧 token 可能已经失效。
此时 sudo 不能从 Server 的哈希恢复缺失明文，必须在面板或 Server CLI 重新签发该节点的安装配置，再执行带 bootstrap 的安装命令。
不应停止仍在上报的旧进程后，才发现配置已失效。

同一连接中的失败续期每 60 秒重发同一个候选。跨连接丢失的候选最多保留 8 个，每个仍受自己的过期时间约束。
达到上限时，不会盲目删除可能已经写入 Agent 磁盘的候选：当前有效连接仍能上报，续期会明确失败并告警；运维需要使用已保存候选恢复，或重新签发安装配置。
写入失败不会无限延长原 token 的有效期；应在原有效期结束前处理权限、磁盘或配置错误。

本机制以一个 node_id 对应一个活跃 Agent 为前提。不支持两个独立进程或克隆配置同时轮换同一个节点身份。
依赖文件系统正确实现 fsync 与原子 rename；测试覆盖故障注入和进程断连，不等同于所有存储硬件的真实断电认证。
