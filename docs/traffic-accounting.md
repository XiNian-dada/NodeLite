# 套餐账本与节点注销

套餐用量按 UTC 自然月累计网卡计数器的增量。首次上报建立基线，用量为 0；
计费方向或月份改变时重新建立基线，Agent 重启导致计数器归零不会产生负用量。

## 计数器异常

账本同时保存上一次的 `uptime_secs`。累计值下降本身不计费，按下面的规则处理：

- uptime 回退：判定为主机重启，立即以当前读数为新基线。
- uptime 未回退：先保持原基线，恢复到原值时不会重复计费。持续 5 分钟仍未恢复时
  （接口被移除、计数器被重置或回绕）才改用当前读数，这段时间内的增量不计入用量，
  同时记下重置前的读数（高水位，随账本落盘）。
- 重建基线后读数回到高水位及以上，视为原计数器恢复（如接口下线再上线），只计高水位以上的部分。
- 仍低于高水位时增量照常计费，但单帧超过 100 Gbit/s 换算量的跳变不计费。
- 升级前写入、没有 uptime 的账本行无法确认主机没有重启，下降时按重启处理。

已知限制：多接口主机上只有部分接口恢复、且跳变低于高水位和速率上限时，这部分字节会被重复计入。
计数器真实重置后增长越过高水位的那一帧，只计高水位以上的部分。

macOS 采集器读取网络计数失败时沿用上一次真实值并将速率置空；从未读到过则放弃这一帧，
与 Linux 一致。

## 存储降级

账本不可用（未加载或历史库不可用）时，配置了限速的节点不会收到任何限速指令，Agent
保持上一次生效的状态；用量不再累计，设置页和流量告警也看不到这些节点的用量。
保持有两个例外，此时会解除限速：节点已取消限速配置，或当前 UTC 自然月晚于本次进程启动的月份。
账本不可用时没有已知用量，所以提高套餐上限不会解除限速；跨月前进程启动时已存在的限速，
最晚保持到下一个自然月。解除后到账本恢复前，该节点不受套餐限速约束。
比较基准在服务重启时重置为当月：账本持续损坏时，重启会让更早月份的限速继续保持到重启当月结束。
账本存在非法行（类型错误、负数、未知计费方向）时整体判定为不可用，不跳过单行，
否则该节点的用量会被后续写入覆盖。加载失败每 30 秒重试一次，修复数据后无需重启。

writer 只记录哪些节点有变更，落盘时读取其最新状态，因此旧内容不会覆盖新状态，更新也不会
被队列拒绝。写入失败时按节点保留内容，以 1 秒起、最多 30 秒的间隔重试。写入内容是绝对值，
重试幂等；内存占用受节点数约束。节点注销或取消套餐产生的删除会覆盖保留的更新。
未落盘的用量不会永久丢失：基线与用量在同一行提交，重启后回到上次提交的状态，只要主机
没有重启，下一帧的差值就会补回这部分用量。

`/readyz` 的 `problems` 用 `traffic_ledger_unavailable` 与 `traffic_write_failed` 标记，
这两项只把 `status` 置为 `degraded`，不会触发 503。`signals` 与 `/metrics` 提供可用性、
写失败次数、最近成功时间和待写节点数；关闭时未能落盘的节点数写入错误日志。

## 节点注销

设置页注销节点会撤销凭证、移除实时节点，并清除内存和 SQLite 中的活动套餐账本。
只有删除事务落盘后才返回成功；先前排队的用量更新不能覆盖这次删除。
清理失败会返回错误并保留凭证撤销结果，重启时会再次按有效注册表清理孤立账本。
注册表重载也会清理已注销节点。重新登记相同节点 ID 后，用量从新主机的首次上报基线开始。

历史趋势与审计日志不属于活动套餐账本。注销节点不会主动删除这两类数据，
它们继续按各自的保留策略清理；历史趋势默认保留 14 天，审计保留期由配置决定。
